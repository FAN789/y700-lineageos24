# A/B OTA 保留与失败检查

补丁 0007 保留媒体 Codec2 的失败状态检查；0008 修正 addon.d 在非 system 分区执行的问题；0009 补齐已安装 Magisk 的保留入口和错误传播。它们属于后续构建的源码改动，不代表已有公开固件已经包含这些修复。

## 分区和数据

自动流程只构建标准完整 A/B 更新。检查拒绝擦除／降级元数据，原生验证严格限定 12 个固件分区，不携带 userdata、metadata、ABL、NV 或校准分区镜像。升级不格式化用户数据；升级前仍应保存工作并制作独立、完整校验的备份。

内核检查直接从已提取的 OTA boot 镜像读取配置，要求命名空间、seccomp 和 SELinux 支持保留。它不以源码配置文件代替实际内核检查，也不替代升级后的运行测试。

## GApps 与已有 root

GApps 使用 LineageOS 原生 addon.d v3 的备份／恢复流程。system 挂载次数被重置时，现有 30-gapps.sh 或 99-magisk.sh 仍可触发保留；vendor 的 checkpoint_gc 不再错误调用 system 的备份脚本。

如果系统已有 `/data/adb/magisk/addon.d.sh`，而缺少 system 的 99-magisk.sh，临时 addon.d 集合会引入该已安装版本自带的官方脚本。由 Magisk 处理其标准 A/B 目标槽逻辑，不从构建端植入补丁 boot、不把某台设备的镜像或密钥复制进固件。无 Magisk 的设备不会因此获得 root。已有保留钩子不会被覆盖。

备份／恢复阶段失败必须向上返回，阻止更新被错误标记为成功。更新器在挂载阶段直接报告致命 postinstall 错误，不会被后续可选的 dex 优化步骤吞掉。保留 SELinux、VINTF、依赖、签名及原生分区校验。

## 验证与首次迁移

CI 在远程构建前运行隔离文件系统中的真实脚本回归测试，以及使用实际 MountPartition 函数体、替代块设备／挂载／SELinux 后端的 C++ 路由测试。测试不调用真实 Magisk、块设备或挂载。构建后检查打包脚本逐字节一致、实际更新器包含修复入口，以及完整原生验收和内核配置。

首次安装此修复时，执行更新的仍是旧系统的 update_engine，因此旧版 vendor 阶段的警告可能出现最后一次。新目标系统的保留脚本在该次更新中已可执行；更新器路由修复从新系统的下一次 OTA 开始生效。不能把首次迁移仍有旧警告当作新代码已经执行，也不能凭脚本测试宣布实机 root 自动保留已通过。

每个候选仍需确认安装前后的 GApps 文件、Magisk 目标槽读回、数据和原有功能。未通过的候选不得推广到 OTA feed；构建、发布和刷入是独立步骤。
